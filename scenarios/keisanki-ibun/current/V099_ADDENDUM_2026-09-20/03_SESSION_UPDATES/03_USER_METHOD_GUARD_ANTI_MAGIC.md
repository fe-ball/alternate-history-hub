# User Method Guard — anti-magic rollback prohibition

Status: AUTHORITATIVE SIMULATION-METHOD GUARD
Origin: explicit user direction in the 2026-09-20 audit session

## Core point

The scenario must not drift into an **anti-magic** method.

The computer is not magic. It does not create:
- horsepower;
- aluminum, nickel or fuel;
- machine tools;
- skilled labor;
- flight hours;
- ships, bases or crews.

But that constraint must **not** be inverted into a rule that Japanese performance, reliability, production, C2 or institutional quality should be pushed back toward historical values merely because a Branch result looks unusually strong.

Historical distance is not a balancing parameter.

## Required audit rule

Do not say:
- "too far from history, so reduce it";
- "Japan historically could not do this, so use the historical median";
- "no exact Branch number exists, therefore restore the historical value";
- "the development is more than N months / one year early, therefore forbid it".

Instead:
1. identify the requirement available to the actors at that date;
2. identify the physical / industrial / organizational constraints;
3. identify which repeated calculations, design-space searches, tolerance analysis, test feedback and information-processing loops are accelerated;
4. reconcile duplicate effects at shared intermediate variables;
5. allow effects at distinct causal stages to compound;
6. stop only at a demonstrated bottleneck.

If the result is far from history and the causal chain supports it, keep the result.

If the evidence is incomplete, widen the WORKING band or leave the item OPEN.

## Persistence of earned capability

A Branch capability already earned through dated development, test, production or institutional learning does not spontaneously revert to historical Japanese median.

This applies especially to:
- production quality / lot control;
- maintenance fault diagnosis;
- radar/visual plotting and fighter-direction procedure;
- formatted radio reporting and EMCON;
- photo-ISR overlap, mosaicking, coordinate handling and previous-image comparison;
- confidence labels such as CONFIRMED / CORRELATED;
- air-ground separation;
- carrier-air cellularization;
- physical / serviceable / crewed / mission-ready accounting.

These capabilities may degrade only when a causal mechanism exists, such as:
- factory damage;
- material or fuel-quality decline;
- loss of skilled maintainers;
- depot / tool / spare-part destruction;
- training-time collapse;
- communications/C2 destruction;
- combat loss of specialist cadres;
- long-range deployment and supply burden.

## Performance guard

Do not nerf a Branch aircraft merely because the number looks high.

A downward revision requires a physical or operational reason:
- weight;
- drag;
- altitude power;
- propeller efficiency;
- cooling;
- stores state;
- structural limit;
- fuel state;
- production dispersion;
- maintenance deterioration;
- crew/training state.

Prototype best, production standard and field median remain separate.

## Anti-false-precision rule

Do not open a complete national ledger for every screw.

Default audit hierarchy:
1. major shared bottleneck (e.g. 誉 engine wallet);
2. airframe-factory feasibility;
3. physical -> serviceable -> crewed -> mission-ready;
4. theater allocation.

Open propeller, gun, radio, gear, hydraulics, materials or subcontractor ledgers only when evidence shows that they bind the plan.

## Readability

For Japanese-facing prose, prefer aircraft name + model code:
- 四式戦闘機 疾風（Ki-84）
- 艦上攻撃機 流星（B7A）
- 艦上偵察機 彩雲（C6N）
- 陸上爆撃機 銀河（P1Y）

Avoid long code-only sequences where a Japanese name exists.
